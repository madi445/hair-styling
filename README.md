# Silk Styling

## Стек и структура

Это существующий проект на Node.js без frontend-фреймворка. Сервер использует встроенный `node:sqlite` (SQLite), HTML, CSS и браузерный JavaScript.

- `index.html` - лендинг курса `/` и `/course/`.
- `backend/server.js` - API, сессии, проверка статусов и защищённый видеопоток.
- `backend/config.js` - цены, адрес продавца и список уроков.
- `frontend/` - страницы оплаты, подтверждения, кабинета, урока и админки.
- `data/` - автоматически созданная SQLite-база и приватные скриншоты.
- `videos/` - локальное видео для разработки; HTTP-сервер не раздаёт эту папку как static.

Требуется Node.js 22.5 или новее. SQLite API встроен в Node.js и пока помечен экспериментальным.

## Локальный запуск

PowerShell:

```powershell
$env:ADMIN_PASSWORD = 'ЗАДАЙТЕ_НОВЫЙ_ДЛИННЫЙ_СЕКРЕТ'
npm start
```

Откройте `http://localhost:3000`. Для проверки сценария оплаты выполните `npm test`.

Для Live Server на `127.0.0.1:5500` API разрешает запросы с localhost, но маршруты checkout и страницы курса обслуживаются приложением Node.js; для полного сценария открывайте `http://localhost:3000`.

## Деплой на Render

В корне есть `render.yaml` для Node web service в Frankfurt с 5-ГБ persistent disk. План сервиса платный: Render не предоставляет persistent disk для бесплатного сервиса. Создайте Blueprint из GitHub-репозитория в Render Dashboard, проверьте сгенерированный `ЗАДАЙТЕ_НОВЫЙ_ДЛИННЫЙ_СЕКРЕТ` в настройках сервиса и не публикуйте его. Проверка готовности сервиса выполняется через `/api/health`.

Видео намеренно не копируется в Git при новых коммитах. После создания сервиса настройте SSH в Render и загрузите файл командой по SSH-адресу, который Dashboard показывает для сервиса:

```powershell
scp -s .\videos\IMG_1016.MOV <service-user>@ssh.frankfurt.render.com:/var/data/IMG_1016.MOV
```

В текущем Git-коммите видео уже записано обычным blob размером 1,53 ГБ. Поэтому Render не сможет клонировать репозиторий до очистки Git-истории; одного `.gitignore` недостаточно. Историю нужно переписать, удалить blob и отправить ветку заново. Это меняет commit hashes и требует force push — согласуйте такую операцию с участниками репозитория заранее.

## Kaspi и акция

Изображение Kaspi QR находится в `assets/kaspi-qr.jpeg` и отображается на странице оплаты. Это публичный платёжный реквизит, поэтому файл должен попадать в production-сборку. Не заменяйте его случайным QR.

При первом запуске создаётся `data/silk-styling.sqlite`, и время начала акции сохраняется в базе. С этого момента цена 30 000 ₸ действует 7 суток, после чего серверная цена меняется на 50 000 ₸. Чтобы задать начало до первого запуска, установите `PROMO_START_AT` в ISO-формате, например `2026-10-01T09:00:00+05:00`. Для уже созданной базы дата хранится в SQLite.

Платежи принимают скриншот PNG/JPG/WebP до 5 МБ, сумму, дату, контакт и пароль кабинета. Платёж всегда создаётся со статусом `Pending`; администратор вручную меняет его на `Paid` или `Rejected` в `/admin/payments/`. Клиентская форма не выдаёт доступ. Повторная отправка защищена ключом идемпотентности, номер платежа уникален, а выдача права на курс создаётся один раз.

Автоматическая проверка Kaspi не включена: официальные API/webhook-реквизиты не предоставлены. Серверный переход статуса отделён от формы и админского UI, поэтому позже его можно вызвать из обработчика официального webhook после проверки подписи провайдера. До подключения webhook не считайте скриншот автоматическим доказательством оплаты.

## Администратор

`ADMIN_PASSWORD` обязателен для входа в `/admin/payments/`. Пароль хранится в окружении, а не в frontend или SQLite. Для production используйте HTTPS и секреты платформы размещения; включите `NODE_ENV=production`, чтобы cookie сессии получала флаг `Secure`.

## Доступ к видео

Страница `/course/lesson/lesson-1/` запрашивает видео через `/api/lessons/lesson-1/video`. Каждый запрос, включая HTTP Range для перемотки, проверяет сессию и статус `Paid`. Не публикуйте видео через CDN/static storage с общедоступным URL. Для production задайте `VIDEO_PATH` на приватное подключённое хранилище; можно заменить поток на подписанные краткоживущие URL VdoCipher/Bunny Stream.

Сервер накладывает пользовательский watermark в плеере. Это не DRM и не предотвращает запись экрана. Для серьёзной защиты используйте специализированный видеохостинг.

База и подтверждения оплаты находятся в `data/` и исключены из Git. Для production используйте постоянный приватный диск или managed SQL и настройте резервное копирование.
